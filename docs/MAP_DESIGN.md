# 《渊塔守卫》地图与关卡设计提案 v1.1

- 状态：**已确认并实现**（2026-10-22 初版；2026-10-23 同步 v1.8：原型扩到 6、词缀扩到 8）
- 目标：解决当前「每局都是一条单入口路径、地图体验重复」的问题。

---

## 1. 现状问题

- 每局地图由同一算法生成，结构上都是「左进右出的一条单路径」。
- 每波所有敌人从同一个传送门出现，防守只需要覆盖一条线。
- 地图之间只有形状差异，没有机制差异；玩家感受不到“换了一张图”。
- 没有路线选择、分叉、汇流、动态入口，塔位与射程的价值单一。

## 2. 同类游戏怎么做的

### 2.1 Kingdom Rush：交叉口就是战场

- 关卡由多条路径、多个出生点和出口组成，路径在路口交汇。
- 设计师会在交叉口周围给足塔位，让玩家把路口变成“绞肉机”。
- 后期关卡会改变路线、打开新路径，惩罚只堆一个路口的打法。
- 结论：**多入口 + 汇流点 + 关键塔位**，比单纯加长路径更有效。

### 2.2 Rogue Tower：分叉是核心策略层

- 地图随波次向外扩张，路径经常分叉；玩家可以选择让敌人一次来一路，或汇合后吃 AoE。
- 地图可以从 1 条路开始，逐渐变成双路、三路甚至十几条路。
- 多路会让“覆盖所有角度”变难，迫使玩家做取舍。
- 结论：**分叉/汇流本身就是玩法**，不只是地图装饰。

### 2.3 Bloons TD 6：交替路径 vs 同时路径

- 有的地图多路但每波只激活一条；有的地图多路同时出怪。
- 同时路径要求塔位能覆盖两条路，交替路径则允许玩家轮换防守重点。
- 结论：**“哪一路这波会出怪”可以成为波次信息与决策点**。

### 2.4 Infinitode 2：路线规则与传送门

- 自定义地图最多可放 8 个出生传送门。
- 典型关卡会“分裂 → 汇合 → 再分裂”，不同分支出不同敌人类型。
- 传送门/逻辑门可以限制某些敌人走特定路线。
- 结论：**入口数量、分支类型、敌人分流规则**是可持续扩展的地图维度。

### 2.5 其他参考

- 《Siege of Centauri》把「入口数、分叉、出口数、堵路复杂度」列为地图设计的主要杠杆。
- 《Fieldrunners 2》证明“开放迷宫、玩家自己造路”很有深度，但需要寻路、堵路规则与防摆烂设计，首版不建议。
- 地图设计文章普遍强调：转弯与交叉口是天然的高价值塔位，关键路口必须留出建造点。

## 3. 推荐方案：多入口分支地图 + 地图三选一 + 地图词缀

### 3.1 路径图，而不是一条折线

每张地图由一张有向图构成：

```
spawn A ──┐
          ├── 汇流点 ── 主路 ── base
spawn B ──┘
```

- 1–3 个出生传送门；1 个基地。
- 路径可以在中途汇合，共享最后一段“主路”。
- 允许多个入口共用部分路径，但不做真正的平面交叉（避免桥/立交的渲染复杂度）。
- 每个入口有独立路径长度、转弯数、可建造塔位；路径长度差控制在合理范围，避免某一路必漏。
- 汇流点周围预留高价值塔位（覆盖两条路）。

### 3.2 地图原型（每局从中抽取）

| 原型 | 入口 | 结构 | 体验 |
|---|---|---|---|
| 单径峡谷 | 1 | 单路蛇形 | 教学/稳定，适合新手 |
| 双径汇流 | 2 | 两条路中途汇合 | 前期分兵，汇流点 AoE 爆发 |
| 三径裂隙 | 3 | 三路在不同位置汇合 | 覆盖压力大，塔位取舍明显 |
| 环形回廊 | 2 | 两条长环线汇合到基地 | 路径长，适合减速/持续输出 |
| 交叉回廊 | 2–3 | 先汇流、再分叉到基地 | 需要二次分配火力 |
| 折返长廊 | 1 | 单入口反复折返 | 直线火力难以覆盖全程，需沿路分段布防 |

- 原型由地图种子决定；同一每日挑战种子对所有玩家一致。
- 地图生成后校验：每个入口都能到基地、路径不贴身、关键汇流点附近有可建造格、可建造比例达标。

### 3.3 每波激活哪些入口

- 波次数据增加「入口计划」：
  - 前 5 波：单入口（随机或固定）。
  - 6–14 波：逐步出现双入口。
  - 15 波后：双/三入口混合。
  - 首领波与第 30 波：所有入口同时出怪。
- HUD 显示本波激活的入口图标；入口有出怪预警。
- 玩家需要判断：这波主压力在哪一路、要不要临时卖塔/补塔。

### 3.4 开局地图三选一

- 服务端用本局种子生成 3 张候选地图，返回预览信息：
  - 原型名称、入口数量、路径长度、可建造数量、词缀。
- 玩家在难度选择后进入「选择地图」弹窗，三选一。
- 每日挑战同样三选一，保证同种子同候选。
- 这样每局不只是“换形状”，而是开局就做一次战略选择。

### 3.5 地图词缀（每个候选随机 1 个）

v1.4 实装 4 个，v1.8 扩到 8 个，全部是“有得有失”，不做纯负面：

| 词缀 | 效果 |
|---|---|
| 富矿 | 金币收入 +20%，敌人生命 +10%（分数 ×0.95） |
| 疾风 | 敌人移速 +14%，击杀金币 +12% |
| 薄雾 | 防御塔射程 -8%，最终分数 +5% |
| 裂界 | 多一个入口，敌人生命 +5%、移速 +3%，金币收入 +10%（分数 ×1.05） |
| 重甲 | 敌人生命 +18%、移速 -4%，击杀金币 +10%（分数 ×1.06） |
| 悬赏 | 击杀金币 +28%，最终分数 -4% |
| 远眺 | 防御塔射程 +12%，击杀金币 -6%（分数 ×0.97） |
| 涌潮 | 敌人移速 +22%，击杀金币 +15%（分数 ×1.07） |

- 词缀在选图卡片上明确展示。
- 计分：给地图一个 `scoreMul`（实现范围 0.90–1.25），服务端结算时乘入，避免“选简单图刷榜”。
- 词缀和地图原型都写入远征记录与排行榜展示。

### 3.6 不做的事情（首版）

- 不做开放迷宫/玩家堵路：需要寻路、堵死判定、防恶意摆塔，改动过大。
- 不做多基地/多核心：UI、计分、失败条件都会变复杂。
- 不做局内换图/章节推进：塔与遗物跨图继承的规则容易失衡，先用地图形状与入口变化提供差异。

## 4. 技术改动概览

### 4.1 共享地图模型

```js
{
  archetype: 'twin-merge',
  lanes: [ { id, spawn, pathCells, polyline, length } ],
  junctions: [ { cell, incoming: [laneId], outgoing: [laneId] } ],
  base,
  buildable,
  blocked,
  rocks,
  modifier: 'rich',
}
```

- 服务端生成 3 个候选：`generateMapCandidates(seed, count)`。
- 客户端移动改为沿 lane 的 polyline；敌人出生时绑定一条 lane。
- 汇流后共享主路；渲染器绘制多入口/多路径与入口标记。

### 4.2 波次与入口

- `generateWave(seed, wave, difficulty, portalCount)` 返回 groups，每组带 `portal`（0..n-1 或 `all`）。
- 客户端按组分配出生入口；同一组内可轮换入口。
- 服务端记录本局地图候选/选择/词缀，结算时使用 `scoreMul`。

### 4.3 渲染与 UI

- 多个传送门（不同颜色/编号）、基地、汇流点高亮。
- HUD 增加「本波入口」指示；地图选择弹窗展示缩略图/入口数/词缀。
- 塔位预览与射程圈不变；汇流点附近塔位更有价值，天然形成策略点。

### 4.4 平衡

- 多入口会提高覆盖难度，保持总血量预算接近，但按入口拆分。
- 机器人需要按“覆盖多少条路”评分塔位，不再只按单路覆盖率（当前实现对每条 lane 采样）。
- 重新跑 40 种子 × 每种子 3 张候选地图，按原型/词缀报告通关率，避免多入口直接变成难度墙。
- 词缀只作为乘数/局部规则，不能让某一词缀成为唯一最优。

**v1.4 机器人平衡结果（全解锁、远征，详见 `docs/BALANCE.md`）**：

| 原型 | 通关率 | 说明 |
|---|---|---|
| 单径峡谷 | 37% | 覆盖简单，作为基准 |
| 双径汇流 | 48% | 汇流段塔位价值高，机器人口径偏易 |
| 环形回廊 | 33% | 长路径利于减速与持续输出 |
| 三径裂隙 | 27% | 三路分摊火力 |
| 交叉回廊 | 13% | 需二次分配火力，机器人明显吃亏 |

- 计分按难度补偿：交叉回廊 `scoreMul` 1.10、三径裂隙 1.07、环形回廊 1.02、折返长廊 1.00、双径汇流 0.97、单径峡谷 0.95（再乘词缀倍率）。
- 词缀全解锁远征通关率：薄雾 28% / 富矿 32% / 疾风 34% / 裂界 32%；零解锁下排序变化，说明词缀强弱依赖解锁状态，不做单一“唯一最优”结论。
**v1.8 复测结果（全解锁、远征，详见 `docs/BALANCE.md`）**：

| 原型 | 通关率 | 说明 |
|---|---|---|
| 折返长廊 | 53% | 单入口折返，机器人沿路布防即可，口径偏易 |
| 双径汇流 | 46% | 汇流段塔位价值高 |
| 环形回廊 | 44% | 长路径利于减速与持续输出 |
| 单径峡谷 | 42% | 覆盖简单，作为基准 |
| 交叉回廊 | 39% | 需二次分配火力 |
| 三径裂隙 | 26% | 三路分摊火力，最低 |

- 词缀通关率从高到低：悬赏 64%、远眺 55%、薄雾 50%、重甲 39%、富矿 38%、裂界 38%、疾风 31%、涌潮 25%。
- 机器人策略不会建造战旗/震荡/狙击塔；新塔对地图差异的影响尚未纳入模拟。

### 4.5 测试

- 地图生成不变量：每个入口可达基地、路径不重复、汇流点有效、可建造比例、同种子一致。
- 入口计划：每波至少一个入口；首领波/最终波全入口；入口索引合法。
- 端到端：多入口地图能正常出怪、索敌、清波；地图三选一可进入；旧单路径地图兼容。
- 性能：多路径渲染不增加明显开销；动态性能测试保持通过。

## 5. 实施顺序建议

| 阶段 | 内容 | 目的 |
|---|---|---|
| M1 | 路径图 + 2/3 入口原型 + 单入口激活 | 先让地图“看起来不一样” |
| M2 | 每波多入口 + 汇流点 + 入口 HUD | 让多入口真正影响决策 |
| M3 | 开局地图三选一 + 地图词缀 + 计分 | 让每局开局就有选择 |
| M4 | 平衡重跑、移动端验收、文档/部署 | 保证三档难度与手机端不崩 |

---

## 6. 备选方案与取舍

| 方案 | 趣味上限 | 开发成本 | 风险 | 结论 |
|---|---|---|---|---|
| 多入口分支（本提案） | 高 | 中 | 平衡与地图生成 | **推荐先做** |
| 开放迷宫/堵路 | 很高 | 高 | 寻路、堵死、摆烂 | 后续版本 |
| 章节式多地图 | 高 | 高 | 塔/遗物跨图继承 | 后续版本 |
| 多基地/多核心 | 中高 | 中高 | UI/失败条件 | 后续版本 |
| 只加长路径/换皮 | 低 | 低 | 仍然无趣 | 不采用 |
