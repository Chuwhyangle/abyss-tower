## Proposal

`public/js/sim.js` 目前是 2523 行、105 个方法的单一 `Simulation` 类，混合了波次调度、敌人 AI/寻路、塔逻辑、投射物、伤害结算、技能系统、遗物/mod、海克斯集成、可破坏物与快照/计分等职责。行为测试充分（全量 1395 个用例），但类内没有职责边界：任何新机制都必须修改同一文件，评审面、并行开发与定位成本随规模上升。本任务在不改变任何可观测行为与 RNG 调用顺序的前提下，把 `Simulation` 收缩为状态根 + 编排者，把具体职责下沉为可独立测试的协作对象。

## Plan

1. 新建 `public/js/sim/` 目录；每个系统模块导出一个类，构造时接收 sim 状态根（不持有全局单例、不自行创建 RNG）。
2. 按 `Simulation.update()` 的现有调用顺序机械迁移（RNG 调用顺序必须逐字节不变）：
   - `wave-director.js`：beginWave / spawnDue / spawnEnemy / completeWave
   - `enemy-system.js`：updateEnemies / auraBuffFor / updateRanged / boss 阶段
   - `tower-system.js`：makeTower / towerCost / canBuild / place / upgrade / evolve / sell / refreshTowerStats
   - `combat-system.js`：dealDamage / hitEnemy / killEnemy / flushSplits / cleanup
   - `projectile-system.js`：fire / updateProjectiles / impact
   - `skill-system.js`：initSkill / castSkill / castMeteor / emberChain / chrono / stasis / overdrive
   - `relic-system.js`：getRelicLevel / addRelic / applyOffer / recomputeMods
   - `destructible-system.js`：destructibleAt / destructibleAura / destroyDestructible / applyDestructibleEffect / spawnDestructibleSwarm
   - `snapshot-mapper.js`：toSnapshot / save / savePreWave / nextWavePreview / getHud
3. `Simulation` 保留现有公共字段与方法签名，方法体改为对系统的薄委派；`update()` 的步骤顺序保持不变。
4. 每迁出一个系统即补该系统边界测试；迁移全程用现有确定性/快照用例做回归。
5. 新增 `tests/sim-systems.test.mjs`：导出面快照、`sim.js` 行数上限、系统模块存在且被组合、同 seed 快照一致。
