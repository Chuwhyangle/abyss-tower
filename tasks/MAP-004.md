## 背景

MAP-003 已定义可破坏物数据与布点。本任务把拆除、奖励、虫巢生成、图腾光环接入模拟层，并让快照在刷新后保持已拆除状态。

## 要求

- `Simulation` 增加 `destructibles` 运行时状态：由 `map.destructibles` 深拷贝，含 `destroyed`、`cost`、`effect`。
- 新方法 `destroyDestructible(id)`：校验存在/未拆除/金币足够 → 扣费 → 标记销毁 → 应用效果 → 释放该格可建造 → 存档；返回 `{ok, reason}`。重复调用幂等。
- 效果：
  - `vein` +110 金；`cache` +25 金并 +1 基地生命（封顶 maxBaseHp）；`obelisk` 写入永久 `towerDamageMul`（最多 3 层）；`nest` 用当前波次强度生成 6 只 `swarm`（走 `spawnEnemyAt`/同类接口，不推进波次计数）；`totem` 关闭光环。
  - `totem` 光环在 `updateEnemies` 中生效：移速 ×1.08，生成时生命 ×1.10；拆除后立即失效，已生成敌人不回滚。
- 快照（`public/js/shared/snapshot.js`）：记录已拆除 id 列表与石碑层数；`toSnapshot/fromSnapshot` 版本升级并兼容旧快照（缺字段视为空）。
- `canBuild` 必须把未拆除的可破坏物格视为不可建造；摧毁后可建。
- 不新增 UI/渲染；只暴露 `sim.destructibles` 数据与 `opts.onToast` 文案。

## Notes

### 实现

- `public/js/sim.js`
  - 构造期 `this.destructibles = createDestructibleEntries(map.destructibles, opts.destructibleState?.destroyed)`：逐件深拷贝 `{id, type, c, r, cost, effect, destroyed}`，`cost/effect` 取自 `DESTRUCTIBLE_BY_ID`（JSON 深拷贝，运行时不污染注册表）；读档只恢复拆除结果，布点坐标始终以地图为准。
  - `destroyDestructible(id)`：`not-found` / `already-destroyed` / `gold-insufficient` 三种失败均不扣费、不标记、经 `opts.onToast` 给出中文原因；成功则扣费→标记→结算效果→`save()`（整备期落盘，波中由波前快照负责回滚）。重复调用天然幂等（第二次 no-op）。
  - 效果全部由注册表声明式数据驱动：`gold` / `baseHp`（`Math.min(maxBaseHp, …)` 封顶）/ `towerDamageMul`（`obeliskStacks` 自增并封顶 `maxStacks`，立即 `recomputeTowerStats()`）/ `spawn`（虫巢）/ `aura`（图腾无即时结算）。
  - 石碑：`get towerDamageMul()` = `1 + stacks × 5%`，在 `computeTowerStats` 的伤害上作为独立乘子，清波/遗物重算都不清除；快照只存层数。
  - 图腾：`destructibleAura()` 汇总存活图腾；移速倍率在 `updateEnemies` 每帧实时相乘（拆除当帧失效），生命倍率只在 `spawnEnemy` 生成时相乘（已生成敌人不回滚）。
  - 虫巢：`laneProgressNear(c, r)` 把巢穴格中心投影到最近车道的 `{lane, progress}`，再用 `spawnEnemy(type, lane, hpMul, progress)` 依次错开 0.2 格生成 6 只 `swarm`；`wave/clearedWave/spawnQueue/spawnIndex` 全部不变。`currentWaveHpMul()` 波内取本波 `waveDef.hpMul`，整备期用同种子的下一波定义（`generateWave` 是纯函数、不消耗 combatRng）。
  - `canBuild` 增加 `destructibleAt(c, r)` 判定：未拆除占格不可建，拆除后同格立即可建（`map.buildable` 保持地形语义不变）。
- `public/js/shared/snapshot.js`：`SAVE_VERSION` 6 → 7；新增可选字段 `destructibles: { destroyed:[id], obeliskStacks }`，只在真的拆过东西时写入（未受影响的对局存档字节结构不变）；`migrateSnapshot` 收敛重复/非字符串 id 与层数上限，缺字段按空处理；`collectWarnings` 增加 `invalid-destructibles`。
- `public/js/app/run.js`：`beginGame` 增加一行 `destructibleState: snapshot?.destructibles`，让快照真的接回模拟层（刷新后已拆除物件不复活）。非 UI/渲染改动。
- 未改任何 `public/js/ui/**`、`public/js/render/**`、`public/styles.css`。`sim.destructibles` 只暴露数据；名称/图标/描述仍由 MAP-005 从 `DESTRUCTIBLE_BY_ID` 读取。
