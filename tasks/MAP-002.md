## 背景

`server/services/run-service.mjs` 在 create/serialize/chooseMap/serveWave/finish 多处调用 `generateMapCandidates`，每日/本周还用随机词缀做一致性校验；选图 UI 在 `public/js/ui/modals.js`。固定地图必须在服务端、客户端和全部模式里是同一张图。

## 要求

- 服务端所有 `generateMapCandidates` 调用改用固定地图池；删除候选随机词缀校验，改为固定 trait；`mapChoice` 仍为 0..2。
- 每日/本周：同一 day/week 的所有玩家拿到同一组 3 张固定图与固定 trait；不再比较随机 modifier 列表。
- 旧 active run / 回放：`ruleset.mapPool !== 'fixed-v1'` 时回退 `legacyGenerateMap`（只读），不得崩溃；新 run 写入 `ruleset.mapPool='fixed-v1'`。
- `serialize / chooseMap / serveWave / finish / active` 返回的 `map`、`mapMeta`、`modifier`、`portalCount` 均来自固定地图；服务端与客户端 import 同一共享模块，禁止复制地图数据。
- 客户端 `public/js/app/run.js` 的选图/恢复/beginGame 使用固定图；刷新恢复同一张图。
- 选图界面（`public/js/ui/modals.js` + `public/js/ui/shared.js`）：卡片显示固定地图名、真实路径缩略图、固定 trait、scoreMul；移除“随机候选/词缀重掷”文案；三张固定图顺序一致；中英双语；移动端不溢出。
- `public/styles.css` 只做必要的布局/预览样式补充，不改全局风格。
