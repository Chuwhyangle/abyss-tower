## Proposal

当前浏览器验收（tests/browser-*.mjs）只验行为，不验画面与手感；GOAL-005/006 的 AC 依赖 `tests/visual-scenes.mjs`、`scripts/visual-check.mjs`、`scripts/feel-review.mjs`、`scripts/art-review.mjs`，这些入口尚不存在。没有确定性场景与前后对照图，打击感与美术改动只能靠肉眼，回归无法发现，也无法给 goal driver 提供可重复的机械证据。

## Plan

1. `tests/visual-scenes.mjs`：复用 `tests/harness.mjs`，固定 seed、固定模拟步长、固定视口（1440×900 与 390×844），采集 title / lobby / map / combat / result 五个场景；combat 场景用脚本化建塔与刷怪制造稳定混战；输出 PNG、contact sheet 与 `manifest.json`（seed、commit、视口、画质、场景、像素哈希）。
2. `scripts/visual-check.mjs`：从 PNG 与 DOM 读取指标，提供 `--suite feel|art|ui|mobile`：feel 检查命中特效覆盖、飘字可见性、敌方/背景亮度差、特效预算；art 检查单位与背景 ΔE、剪影像素覆盖、背景层次；ui 检查最小字号、对比度、未解锁卡可读性；mobile 检查移动视口布局与触控尺寸。
3. `scripts/feel-review.mjs` 与 `scripts/art-review.mjs`：校验 `docs/FEEL_REVIEW.md` / `docs/ART_REVIEW.md` 是否包含场景、日期、评审者、结论与分数，且结论为通过；缺失或未通过 exit 1。
4. 把 `npm run visual:capture`、`npm run visual:check` 接进 package.json；在 README 写用法。
5. 首轮采集当前基线，生成 `docs/reviews/baseline-*` 对照图，作为后续 before/after。

### 实现要点（落地记录）

- 确定性：固定 seed + 页面初始化脚本固定 `Math.random`；战斗接管后停止 RAF，改为固定 1/60 步进；截图前冻结 CSS 动画并把大厅动态背景重绘到固定相位。战斗帧两次采集像素哈希完全一致；DOM 场景允许指纹容差（`determinism.json` 记录 `meanAbs` / `diffRatio`）。
- feel 的核心判据是「同一帧去掉表现层前后的像素差异占比」（特效层 / 飘字层 / 受击闪白层各有一张参照帧），因此删掉特效或把特效画成背景色都会让覆盖率归零。回归注入：`--inject no-feedback` 与 `--inject effects-invisible`，两者都 exit 1。
- 基线状态：feel / art 通过；ui（HUD 词缀倍率角标 10px）与 mobile（标题页 `.skill-role` 8.5px）在最小字号项上未通过 —— 阈值编码的是 GOAL-006 的目标状态，这两项就是 ART-001 的整改输入。
- 运行时间：单场景 3.2–4.0s，全场景 × 两视口（14 帧）约 29–31s，远低于 60s / 5min 预算。
- 基线对照图已落盘：`docs/reviews/baseline-contact-sheet.png` + `docs/reviews/baseline-manifest.json`。
