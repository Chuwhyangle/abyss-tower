## Proposal

服务端只对 runs 实现了 routes → services → db 的分层（`tests/architecture.test.mjs` 守护：routes 薄、无内联 SQL、依赖 service）。其余路由直接调用 `server/db/*.mjs`，领域规则（排行榜校验、通知偏好归一、赛季边界、审计）住在 db 模块里；`server/routes/profile.mjs` 还有 2 处直接 `db.prepare`。本任务统一分层口径：高价值域补 service 层，路由只做 HTTP 适配，db 模块只做 SQL/仓储，并把架构测试从 runs 扩到全域。

## Plan

1. 在 `tests/architecture.test.mjs` 的注释中写明统一口径：routes 只做 HTTP 适配；services 持有领域规则；db 模块只做 SQL/仓储；为全域新增断言。
2. 新建 `server/services/leaderboard-service.mjs`、`server/services/season-pass-service.mjs`、`server/services/notifications-service.mjs`：把 `db/leaderboard.mjs`、`db/season_pass.mjs`、`db/notifications.mjs` 中的领域规则（校验、归一、边界计算）迁入，db 模块只保留查询/写入原语。
3. 迁移 `server/routes/profile.mjs` 的 2 处 `db.prepare` 到 `db/accounts.mjs` / `db/audit.mjs` 的仓储函数。
4. 对应路由改为依赖 service：`routes/leaderboard.mjs`、`routes/season-pass.mjs`、`routes/notifications.mjs` 删除规则计算，只解析请求与组装响应。
5. 扩展 `tests/architecture.test.mjs`：遍历 `server/routes/**` 断言无 SQL 字面量与 `db.prepare/exec`；断言上述三个路由 import 对应 service；断言三个 service 文件存在。

- 实施：新增 `server/services/{leaderboard,season-pass,notifications}-service.mjs`，承接请求归一（mode/day/season/难度/分页）、赛季窗口与归档时机、排行榜复核说明、通知偏好载荷校验与批量已读语义；三个路由只保留 HTTP 适配。`server/routes/profile.mjs` 的内联 SQL 全部迁入 `server/db/accounts.mjs` 档案仓储（player_kv 读写、进度、成就 id、导出与每日历史对局汇总）。
- 全域收口：`server/auth/rate-limit.mjs` 的 `auth_events` 写入/计数、`server/routes/system.mjs` 的诊断只读查询（PRAGMA/迁移/活跃对局）也迁入 `server/db/accounts.mjs` / `server/db/index.mjs`，因此 `server/routes/**` 与 `server/auth/**` 已零 SQL 字面量、零 `db.prepare/exec`；架构测试把这两层一起纳入断言。为此 Touches 追加 `server/routes/system.mjs`、`server/db/index.mjs`、`server/auth/rate-limit.mjs`。
- 分层边界说明：db 模块保留 SQL 原语与仓储函数，`boardKeyFor` / `seasonBounds` / `validateLeaderboardEntry` 等纯键/边界/反作弊函数仍由 db 模块导出——`services/run-service.mjs` 与多个既有测试直接引用，迁移会跨出本任务 Touches 且破坏既有导出契约；服务层在这些原语之上做请求级策略与流程编排。
