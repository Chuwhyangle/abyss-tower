## 背景

HEX-001 已有十个海克斯的静态定义与 no-op 钩子。本任务在模拟层建立通用运行时框架，让每个海克斯只改自己的模块即可生效，避免十个实现任务争抢 `sim.js`。

## 要求

- `Simulation` 构造参数新增 `hex`（id 或定义）；初始化顺序：基础 mods → `hex.hooks.onRunInit(ctx)` → 重新计算塔属性。`sim.hex` 与 `sim.hexState` 可读。
- 新增/扩展钩子调用点（找不到钩子时安全跳过）：
  - `modifyTowerStats(tower, stats, ctx)`：在 `computeTowerStats` 末尾调用。
  - `towerMaxLevel(tower, base)` / `upgradeCost(tower, base)` / `allowedEvolutions(tower, base)`：供独塔为王扩展等级与多进化；`upgradeTower/evolveTower` 支持一次应用多条进化。
  - `canBuild(type, c, r, ctx)` / `onTowerBuilt(tower)` / `onTowerUpgraded(tower)` / `onTowerRemoved(tower, reason)`：供镜像工程。
  - `sellRatio(base)`：供黄金律法。
  - `onWaveStart(wave, ctx)` / `onWaveEnd(wave, ctx)`：供赌徒之骰；临时 mod 在波末清理。
  - `onEnemyKilled(enemy, ctx)` / `onLeak(enemy, ctx)` / `onHit(enemy, tower, damage, ctx)`：供亡者/熔火/玻璃大炮。
  - `onRelicGained(relic, ctx)` / `relicOfferCount(base)` / `relicRerollCost(base, count)`：供遗物吞噬者（服务端可读同一数据）。
- 塔生命框架：`makeTower` 增加 `maxHp/hp`（默认 null = 无敌）；新增 `damageTower(tower, amount)`，归零时从 `towers` 移除、释放塔位、触发 `onTowerRemoved`、写快照；UI 可读 `tower.hp/maxHp`。
- 友方单位框架：`this.allies` 数组；`update(dt)` 更新存活时间与攻击最近敌人（接口通用）；提供 `render/ally-renderer.js` 最小渲染并在 `render.js` 注册，供亡者军团使用。
- 快照：记录 `hexId`、`hexState`（可序列化）、塔 `hp/maxHp`；版本升级，旧快照无字段时按无海克斯恢复。
- 不实现任何具体海克斯的数值；只保证钩子存在、默认行为与现状完全一致（无 hex 时全量测试不变）。
