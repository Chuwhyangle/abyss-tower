## 背景

代码已较大（多版本），并发开发时因 Touches 重叠（改同一文件）频繁串行。三路架构论证（耦合/竞争热点/并发方案）发现：代码已模块化 60-70%，但每个拆分后都留着一个「聚合点/索引文件」，所有 worker 的功能改动汇聚到它，导致无法并发。本轮重构就是「去聚合点」。

## 范围

1. 阶段0 安全网：touches-conflict 冲突预检 + OWNERSHIP 单 owner 表。
2. 阶段1 拆 i18n ui 域词典。
3. 阶段2 拆 styles.css 为 ~15 分区。
4. 阶段3 UI/render 面板注册表（统一双 UI 装配）。
5. 阶段4 内容注册表拆分（relics/effects，确定性高危）。
6. 阶段5 sim 战斗 hook 总线。

## 退出条件

- AC-088 阶段0 安全网落地。
- AC-089 阶段2 css 分区落地。

## 非目标

- 不改 sim.js 确定性 RNG 顺序（阶段4/5 串行 + 四道门禁 + sim:determinism 双门禁）。
- 不做全量垂直切片（会破坏 shared 前后端共享 + sim 确定性）。
- 不改公共 API 行为（重构保持行为不变）。
